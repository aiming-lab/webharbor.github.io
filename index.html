02 · Motivation

Live sites keep changing. Generated ones lack depth and fidelity.

GUI web agents need environments that look and behave like real websites, yet stay stable enough to evaluate and train on. Live websites change their content, block automation, and hide their most important workflows behind sign-in. Generated environments are controllable, but often lack functional depth, image-rich content, or login-based workflows.

03 · Our approach

Tasks set the scope. Coding agents build. People audit.

We call it docking: replacing a website's live dependencies with local assets, seeded state, and controlled resets, while keeping its recognizable look and behavior. Environments keep evolving: new tasks expose missing functionality, and the same loop extends the site.

01

Task-driven docking

Cloning Amazon's catalog or YouTube's library is impractical, so each environment is scoped to its target tasks: their entry and terminal pages, the entities they inspect, the browser actions they need, and the state they change. We start from WebVoyager's 15 websites and 643 tasks, then cover every website in Online-Mind2Web with new authenticated, state-changing workflows.

Environments keep near-miss alternatives and natural navigation paths, so there are no trivial shortcuts to the answer.

02

Skill-driven synthesis & evolution

A coding agent explores the real site in a browser and records its page hierarchy, URL patterns, controls and appearance. Guided by reusable construction skills, it builds a self-contained web app backed by SQLite with bundled images. It then runs every target task, fixes the first unsupported page or state transition, resets, and runs the task again.

Missing pages become new routes; incomplete workflows get form handlers and persistent state; thin content gets new records.

03

Human-in-the-loop refinement

Contributors propose websites and functional requirements and steer the coding agent. Reviewers compare each environment with the real site, execute every task end to end, turn defects into concrete requests for the coding agent, and write task-specific verifiers and judge rubrics.

In a pilot of 26 websites, coding agents left 13 with visual or asset defects and 14 with broken or shallow interactions. Each environment gets 2–3 review rounds of 1–2 hours.

05 · Results

A 4B agent trained in WebHarbor transfers to the live web.

WebHarbor-4B starts from the same OpenWebRL-4B-SFT checkpoint and uses the same multimodal GRPO objective and GUI harness as OpenWebRL-4B, which was trained on 2,102 tasks across 704 live websites. Only the environments and tasks differ. All 15 WebVoyager websites are held out of training, and Online-Mind2Web's own tasks are not in the suite.

06 · Quickstart

One image. 153 websites. One port each.

All 153 environments ship in one image on Docker Hub, wildawm/webharbor. Site i listens on port 40000 + i, and a token-protected control plane on :8101 resets any site to its seeded state.

pull & run
# the control plane requires a token of at least 32 characters
export WEBSYN_CONTROL_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
# all 153 sites in one image (about 20 GB)
docker run -e WEBSYN_CONTROL_TOKEN -p 8101:8101 \
  -p 40000-40152:40000-40152 wildawm/webharbor:latest
  • Open http://localhost:40001 for Amazon, :40060 for YouTube, … through :40152 for SEC.gov. The control plane starts once every site is ready, about 2–3 minutes in.
  • One site per image for Harbor evaluation and RL: wildawm/webharbor:<site>-v1, e.g. wildawm/webharbor:amazon-v1. To build from source instead, run ./scripts/build.sh in the repository.
  • Each site has sites/<site>/tasks.jsonl; every task carries a judge rubric and a deterministic verifier at sites/<site>/verify/.
reset & run an agent
# restore one site, or all of them in parallel
curl -H "Authorization: Bearer $WEBSYN_CONTROL_TOKEN" \
  -X POST http://localhost:8101/reset/amazon
curl -H "Authorization: Bearer $WEBSYN_CONTROL_TOKEN" \
  -X POST http://localhost:8101/reset-all

# minimal ReAct agent + LLM-as-judge grader
cd agent_demo && uv sync && uv run playwright install chromium
uv run python agent.py --tasks_file ../sites/amazon/tasks.jsonl \
  --task_id "Amazon--0" --out_dir runs/amazon0
uv run python eval_judge.py --run_dir runs/amazon0
